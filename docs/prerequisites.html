Prerequisites

This page covers two distinct setups: what the event organizer does once before the hackathon, and what each participant team does at the start of their session.

If you're a participant: Your organizer has already completed the setup below. Skip to Participant Setup — your repo is ready and waiting.

If you're running the event: Work through the Organizer Setup steps below before the hackathon starts. These are done once, in the org, not by individual participants.

Organizer Setup — Done once, before the event

O-1 — Fork the Repository into a GitHub Organization

  1. Go to the upstream hackathon repository on github.com.
  2. Click Fork and, when asked where to fork to, select the organization you're using for the event (not your personal account). Give it a meaningful name, e.g. ghas-hackathon-2026.
  3. Make sure the fork is public. GitHub Advanced Security features (CodeQL, secret scanning, Dependabot) are free on public repositories. A private repo requires a paid GHAS license.
  4. Share the org repo URL with all participants. This is the single shared repo everyone will work in.

O-2 — Protect the Main Branch

No participant should push directly to main. All work goes through branches and pull requests.

  1. Go to Settings → Branches → Add branch protection rule.
  2. Set Branch name pattern to main.
  3. Enable:
    • Require a pull request before merging — set required approvals to 1
    • Require status checks to pass before merging — add the CodeQL check once it has run at least once
    • Do not allow bypassing the above settings (optional but recommended)
  4. Save the rule. From this point on, main is protected and all participant work must go through PRs.

Tip: You may also want to set a branch naming convention, e.g. team-{name}/challenge-{id}, so PRs are easy to track per team.

O-3 — Enable GitHub Advanced Security

Navigate to the org repo on github.com. Go to Settings → Code security and analysis and enable the following:

  1. GitHub Advanced Security — the top-level toggle that unlocks all features below.
  2. Dependency graph — should already be on by default.
  3. Dependabot alerts — alerts for known-vulnerable packages.
  4. Dependabot security updates — lets Dependabot open automated fix PRs.
  5. Code scanning — this repo ships with a pre-configured CodeQL workflow at .github/workflows/codeql.yml. No default setup needed — the advanced setup workflow takes precedence.
  6. Secret scanning — detects secrets already committed to the repo.
  7. Push protection — blocks new commits that contain secrets before they land.

O-4 — Trigger the First Code Scan

Trigger the initial CodeQL analysis so alerts are ready before participants arrive. Scans typically take 5–10 minutes.

  1. Go to Actions in the org repo.
  2. Select the CodeQL workflow from the left sidebar.
  3. Click Run workflow → Run workflow.
  4. Wait for completion. Results appear under Security → Code scanning alerts.

Note: This repo uses CodeQL advanced setup (a custom Actions workflow). Do not enable the default CodeQL setup — it conflicts with the pre-configured workflow.

O-5 — Verify the Org Repo Is Ready

  • Repo forked into the org and is public
  • Main branch protection rule active — direct pushes blocked
  • GitHub Advanced Security enabled
  • Dependabot alerts and security updates turned on
  • CodeQL workflow has run at least once — Security → Code scanning alerts shows results
  • Secret scanning and push protection enabled
  • Org repo URL shared with all participants

Participant Setup — Done by each team at the start

P-1 — Clone the Org Repo & Create Your Team Branch

You will not fork the repository. All teams work in the same org repo, each on their own branch.

  1. Get the org repo URL from your organizer (e.g. https://github.com/your-org/ghas-hackathon-2026).
  2. Clone it locally or open a Codespace from the org repo (see P-2 below).
  3. Create a branch for your team from main. Use a consistent naming pattern your organizer specifies — e.g.: 
    git checkout -b team-{your-team-name}/challenge-work
  4. Push the branch immediately so it's visible on github.com: 
    git push -u origin team-{your-team-name}/challenge-work

Main is protected. You cannot push directly to main. All your fixes go on your team branch and get merged via pull request.

P-2 — Start Your Dev Environment

Choose one of the following:

  • GitHub Codespaces (recommended): In the org repo on github.com, click the green Code button → Codespaces → Create codespace on main. Once the container is ready, switch to your team branch: 
    git checkout team-{your-team-name}/challenge-work
  • Local dev container: Clone the org repo, open the folder in VS Code, click Reopen in Container when prompted (requires Docker Desktop), then create and switch to your team branch.

Once in your environment, start the application:

cd app && npm start

Juice Shop will be available at port 3000.

P-3 — Verify Your Setup

  • Team branch created from main and pushed to the org repo
  • Dev environment running — Juice Shop loads at port 3000
  • Security → Code scanning alerts shows results in the org repo
  • You can see Dependabot alerts under Security → Dependabot alerts
