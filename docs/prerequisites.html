Prerequisites

Complete these steps once before starting any challenge. The security challenges assume GHAS features are already active — this is where you flip those switches.

Step 1 — Fork the Repository & Start Your Dev Environment

  1. Fork the hackathon repository to your own GitHub account using the Fork button at the top right of the repo page.
  2. Choose one of the following environments:
    • GitHub Codespaces (recommended): Click the green Code button → Codespaces → Create codespace on main. Wait for the container to build and dependencies to install.
    • Local dev container: Clone your fork, open the folder in VS Code, and click Reopen in Container when prompted (requires Docker Desktop).
  3. Once the environment is ready, open a terminal and start the application: 
    cd app && npm start
    Juice Shop will be available at port 3000.

Note: GitHub Advanced Security features are free on public repositories. Make sure your fork is public (the default when forking a public repo).

Step 2 — Enable GitHub Advanced Security

Navigate to your fork on github.com. Go to Settings → Code security and analysis and enable the following:

  1. GitHub Advanced Security — the top-level toggle that unlocks all features below.
  2. Dependency graph — should already be enabled by default.
  3. Dependabot alerts — turns on alerts for known-vulnerable packages.
  4. Dependabot security updates — allows Dependabot to open automated PRs to fix vulnerable dependencies.
  5. Code scanning — this repo ships with a pre-configured CodeQL workflow at .github/workflows/codeql.yml. No default setup needed — the advanced setup workflow takes precedence.
  6. Secret scanning — detects secrets (API keys, tokens, credentials) already committed to the repo.
  7. Push protection — blocks new commits that contain secrets before they land in the repository.

Why this matters: Without these enabled, the Security tab will be empty and the challenges won't have any alerts to work with. Enable everything now so the tools have time to run their first scan while you work through C-00.

Step 3 — Trigger the First Code Scan

CodeQL is pre-configured in .github/workflows/codeql.yml. The workflow runs automatically on push and on a schedule, but you can trigger it manually right now so alerts appear before you need them.

  1. Go to Actions in your fork.
  2. Select the CodeQL workflow from the left sidebar.
  3. Click Run workflow → Run workflow.
  4. Wait for the run to complete (typically 5–10 minutes). The results will appear under Security → Code scanning alerts.

Note: This repository uses the CodeQL advanced setup (a custom Actions workflow). When an advanced setup workflow is present, GitHub's default setup option is unavailable — the two are mutually exclusive. Do not try to enable default setup.

Step 4 — Verify Your Setup

Before starting the challenges, confirm the following checklist:

  • Repository forked to your GitHub account (public repo)
  • Development environment running — Juice Shop loads at port 3000
  • GitHub Advanced Security enabled in Settings → Code security and analysis
  • Dependabot alerts and security updates turned on
  • Code scanning enabled — the CodeQL workflow has run at least once
  • Security → Code scanning alerts shows results
  • Secret scanning and push protection turned on
  • Dependency graph is active and shows detected packages
